## 1. 项目调研结果

### 1.1 gbrain 是什么（来自 README）
- Garry Tan (YC CEO) 私人项目"GBrain"，本名 "Garry's Opinionated OpenClaw/Hermes Agent Brain"。
- 自报规模：**146,646 pages / 24,585 people / 5,339 companies / 66 cron jobs 自跑**。
- 能力栈：混合检索（向量 + BM25 + RRF + source-tier boost + reranker）+ **自建知识图谱** (typed edges: `attended`/`works_at`/`invested_in`/`founded`/`advises`，零 LLM 抽取) + 综合层（`gbrain think` 返回带引用答案，不是切片列表）。
- 关键基准：**P@5 49.1%, R@5 97.9%** (240 页 Opus 生成的丰富文本语料)，相对图谱盲变种 / ripgrep-BM25 / 纯向量 RAG 的 P@5 提升 +31.4 分。
- 部署形态：默认本地 PGLite（嵌入式 PGLite，2 秒启动，零服务器），可选 Postgres + pgvector + Supabase 远程。

### 1.2 与光启的对比（核心差异是"查询时刻的智能综合"）

| 维度 | 光启 | gbrain |
|------|------|--------|
| 存储 | Markdown + Obsidian wikilink | Markdown + Postgres 表 + 向量索引 |
| 检索 | 文件名 / 内容 / `[[nb]]` 跳转 | 混合检索 + 图谱遍历 + LLM 综合 |
| 实体建模 | 隐式（卡片标题暗示） | 显式 typed edges |
| 综合回答 | 人工读卡片 | `gbrain think` 带引用 + gap analysis |

**缺的正是"综合层"**——把分散卡片缝成一张可查询的图。

### 1.3 集成路径选项（已与用户确认）
- **采用**：把 gbrain 作为光启的检索/综合后端——Hermes 调用 `gbrain think` 替代手动翻 wiki
- 即保留 `~/knowledge/wiki/*.md` 作为人类可读的真相源；用 gbrain 作为机器查询接口

## 2. 烟雾测试实操步骤与失败点

### ✅ Step 1: 安装 Bun
- `curl -fsSL https://bun.sh/install | bash` 失败（中文乱码 "系统找不到指定的路径"，写不进 `/c/Users/eitan/.bun/bin/bun.zip`）—— Windows bash 上官方 installer 的 path 处理报错。
- **绕道**：`npm install -g bun` → 装到 `C:\Users\eitan\AppData\Roaming\npm\bun`，版本 **bun v1.3.14**。
- ⚠️ 注意：与官方 bash install 不同——非标准路径 `~/.bun/bin/` 是不存在的，意味着后续 `bun link` 把 gbrain 暴露到全局 PATH 会失败。需用 `npm` 的 bin 目录或在 PATH 里加 `~/AppData/Roaming/npm`。

### ❌ Step 2: 全局安装 gbrain
- `bun install -g github:garrytan/gbrain` 超时 300s，无输出。
- 检查 `~/.bun/bin/`：**空的**——bun 通过 npm 装的，全局 bin 目录不写在这里。

### ⚠️ Step 3: 克隆仓库
- `git clone https://github.com/garrytan/gbrain.git` 超时 60s
- 结果失败：`fatal: your current branch appears to be broken` + 仅 `.git/` 一层。
- 第二次 git clone 报 `fetch-pack: unexpected disconnect while reading sideband packet` + `invalid index-pack output`——Windows 上 git 协议对 unpack 大流量（gbrain 仓库 300+ branches，15M+）处理异常。
- **绕道**：用 `curl` 走 `codeload.github.com` 下载 zip（14.44 MB，写到 `/tmp/gbrain.zip`，time 1m26s），`unzip -q` 解到 `~/gbrain/gbrain-master/`。
- ⚠️ 注意：得到的 zip 仓库无 `.git/`, 因此后续 `git pull` 升级路径不可用——这是一次性快照，不是 git 仓库副本。

### ⚠️ Step 4: `bun install` 给 gbrain 装 deps
- 失败：`error: Integrity check failed for tarball: @ai-sdk/provider-utils / @ai-sdk/openai / marked / bun-types / ai / zod` + `error: ConnectionRefused downloading tarball @types/node@25.5.2`。
- **核心问题**：bun 1.3.14 默认的 npm registry 在这台机器下载 `@types/node` 不通（ConnectionRefused）。同时 bun 对 zod 4 + @modelcontextprotocol/sdk 的 v3 子路径校验失败。
- **绕道**：`npm install --legacy-peer-deps`（nb 强制接受坏 peer deps + 没装 v3 子路径的 zod），155 packages 装到 `~/gbrain/gbrain-master/node_modules/`。有 EPERM cleanup 警告，可忽略。

### ❌ Step 5: 启动 CLI —— **当前阻塞点**
```
$ cd ~/gbrain/gbrain-master && bun run src/cli.ts --version
error: Cannot find module 'zod/v3' from 'C:\Users\eitan\gbrain\gbrain-master\node_modules\@modelcontextprotocol\sdk\dist\esm\server\zod-compat.js'
```
- 原因：npm 装的 `zod` 是 v4，包路径只暴露根入口，不暴露 `/v3` 子目录； 而 `@modelcontextprotocol/sdk` (MCP) 内部硬编码 `require('zod/v3')`——典型的 zod v3→v4 ABI mismatch。
- 修复方向（未实施）：
  - `npm install zod@3 --save-exact` 降级 → 让 npm 把 `zod/v3` 子路径暴露回来
  - 或彻底卸载 npm 装的 155 packages，重走 `bun install + bun link` 官方路径（前提是 registry 网络问题先解）
- 时间成本预估：方案 1 ≈ 10-15 min，方案 2 ≈ 20-30 min。

## 3. 我学到的东西（写入这次失败经验）

### 3.1 Windows + bun + git 的已知困难
1. **官方 bash install 的路径问题**：bun installer 假设 bash 用户用 `~/.bun/`，但 npm 装的 bun 走 `~/AppData/Roaming/npm/`。两者不互通，需要自己配 PATH。
2. **大仓库 git clone**：gbrain 仓库 300+ 分支 + ObjectPack 处理特殊（很可能用了 `sparse-checkout` 或 `graph` 等增量模式），裸 git clone 在 Windows 上经常挂在 `fetch-pack` / `index-pack`。**codeload zip 备份方案要预先准备好**。
3. **bun registry 网络**：默认 Bun 1.3.14 的 npm registry 经常 ConnectionRefused 拉 @types/node。生产环境应该配 `bunfig.toml` 的 registry mirror 或者直接走 npm。

### 3.2 npm 不只是 bun 的降级
- gbrain 是纯 Bun 项目，但 npm `--legacy-peer-deps` 也能装 deps——但代价是 zod v3/v4 ABI 错位、@modelcontextprotocol/sdk 跑不起来。**npm 不是适合生产路径**，只能当测试用。

### 3.3 gbrain 的 MCP 设计对我有启发
- gbrain 的 30 个工具暴露为 MCP（stdio + HTTP）：search / think / capture / graph-query / put-page ...
- 这意味着：**光启可以保留原始 markdown，把"行为层"完全交给 Hermes + gbrain MCP**——我的 .hermes.md 召回策略可以反问 gbrain think，而不是只靠文件 search。
- 真正落地时需要的最小骨架：
  1. `gbrain init` (PGLite)
  2. `gbrain import ~/knowledge/`（把 13 张概念卡塞进库）
  3. `bun run src/cli.ts think "光启的元目的"`（启动 think 子命令，BM25 + 图谱 综合）
  4. 把这条 CLI 调用包成 Hermes 的 skill，挂在 `.hermes.md` Hindsight 之后：先 `gbrain think`，再（如果 gbrain 答不上）走传统 wiki 文件搜索。

## 5. 决策记录
